# 데이터와 파일 관리 규칙

## 디렉터리 정책

```text
data/
├── external/       # 외부 공개 데이터 원본 또는 다운로드 안내
├── raw/            # 사용자/팀 수집 원본, 불변
├── interim/        # 정제·변환 중간 산출물
├── processed/      # 학습 입력 형식
├── splits/         # train/val/test 목록과 생성 기준
└── golden/         # 실제 촬영 기반 고정 평가셋

models/             # 가중치와 ONNX 등 배포 산출물
artifacts/          # 실행별 예측, 체크포인트, 데모 캡처
reports/            # 사람이 읽는 성능·오류 분석 보고서
```

## 원칙

- `data/raw/`의 원본은 수정하지 않습니다. 변환 결과는 새 단계에 씁니다.
- 이미지 ID와 라벨 ID를 분리하고, 파일명에 개인정보를 넣지 않습니다.
- 데이터셋마다 출처, 라이선스, 받은 날짜, 버전, 해시를 기록합니다.
- 연속 촬영·동일 의류·동일 사용자 이미지가 서로 다른 split에 섞이지 않게 그룹 단위로 분할합니다.
- 골든셋은 모델 튜닝에 사용하지 않고 버전으로 고정합니다.
- 사용자 삭제 요청이 학습 후보와 파생 데이터까지 전파될 수 있도록 원본 계보를 기록합니다.

## Git 정책

Git에 포함:

- 스키마, 작은 예제, 다운로드/전처리 스크립트
- split 생성 규칙과 파일 목록(개인정보가 없을 때)
- 실험 설정, 지표 요약, 문서

Git에서 제외:

- 사용자 사진과 공개 데이터 원본
- 모델 가중치와 대용량 체크포인트
- API 키와 로컬 환경 파일
- 업로드 파일, 캐시, DB, 실행 산출물

## 계획 문서 규칙

- 위치: `plan/`
- 이름: `YYMMDD_HHMM_제목.md`
- 회의 결과에는 확정 사항, 담당자, 기한, 보류 사항을 구분합니다.
