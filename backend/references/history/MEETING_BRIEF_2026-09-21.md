# 2026-09-21 MyFit:Core 착수 회의 브리핑

## 30초 설명

MyFit:Core는 여러 벌의 옷을 한 번에 촬영해 디지털 옷장으로 만들고, 날씨·일정·사용자의 마이크로 추구미를 반영해 실제 보유 옷으로 코디를 추천합니다. 추구미 OOTD 피드에서 발견한 스타일을 내 옷장의 유사 아이템으로 바꿔주는 `내 옷장으로 따라입기`가 장기 리텐션 루프입니다.

## 이번 재기획에서 달라진 점

| 초기안 | 재기획안 |
|---|---|
| 한 벌씩 등록 | 최대 6벌 원샷 검출·분할·일괄 편집 |
| 일반 스타일/날씨 추천 | 15대 추구미 + 날씨 + TPO |
| 개인 옷장 유틸리티 | OOTD 소셜 피드와 Styling Mimic |
| 카테고리 분류 중심 AI | 검출·분할·속성·임베딩·추천의 복합 파이프라인 |

## 흡수해야 할 핵심 개념

- Detection은 옷이 어디 있는지 찾습니다.
- Segmentation/Matting은 각 옷의 픽셀과 투명 배경 이미지를 만듭니다.
- Attribute Tagging은 카테고리·색상·패턴을 붙입니다.
- Aesthetic Embedding은 15대 추구미와의 가까움을 수치화합니다.
- Recommendation은 날씨 부적합을 제거한 뒤 추구미/TPO 조합을 순위화합니다.
- Styling Mimic은 타인의 아이템과 내 옷장 후보를 카테고리·속성·임베딩으로 매칭합니다.

## 가장 중요한 판단

현재 문서의 MVP는 완성형 앱에 가깝습니다. 원샷 CV, 추천, 기상청, 캘린더, 전체 소셜 CRUD, 벡터 검색, 세 가지 소셜 로그인과 인프라를 동시에 구현하면 각 기능의 완성도가 낮아질 가능성이 큽니다.

권장안은 **M0 기술·UX 검증을 프로젝트 MVP로 확정하고, M1을 여유 범위로 두는 것**입니다. 상세 범위는 `MVP_SCOPE_REVIEW.md`에 있습니다.

## 오늘 반드시 결정할 7가지

1. 평가 대상은 M0, M1, 전체 범위 중 어디까지인가?
2. 모바일 웹인가 네이티브/크로스플랫폼 앱인가?
3. 15대 추구미의 정확한 목록과 대표 무드보드는 무엇인가?
4. 옷끼리 겹치지 않는 Flat Lay만 허용할 것인가?
5. 원피스·세트업·잡화는 어떤 카테고리로 처리할 것인가?
6. 소셜 피드는 실제 사용자 CRUD인가, 고정 샘플 기반 시연인가?
7. 2초·90%의 측정 환경과 지표 정의는 무엇인가?

## 권장 첫 2주

### AI

- Multi-item Flat Lay 30~50장 소규모 검증셋 제작
- Detection + segmentation 후보 2개 이하로 베이스라인 비교
- 대분류와 대표색 결과 스키마 확정
- 15대 추구미 정의서 및 제로샷 임베딩 탐색

### Backend

- Garment batch/draft/item, analysis job API 계약
- 이미지 업로드와 비동기 상태 전이 설계
- 기상청 API 최소 연동과 내부 WeatherSnapshot 스키마

### Frontend

- 촬영 가이드 → 분석 대기 → 일괄 수정 → 저장 프로토타입
- 추구미 선택과 코디 3종 카드 와이어프레임
- AI 실패·부분 성공·재시도 UX 포함

### 공통

- M0 데모 시나리오와 승인 기준 고정
- 이벤트 이름과 KPI 분모/분자 정의
- 개인정보, 공개 범위, 학습 재사용 동의 구분

## 회의 종료 조건

- 한 문장 MVP와 제외 목록
- 15대 추구미 정의 작업의 담당자·마감
- 촬영 조건과 평가 이미지 수
- AI/BE/FE 인터페이스 오너
- 첫 번째 통합 데모 날짜
- 2초·90% 목표의 정확한 측정 정의
