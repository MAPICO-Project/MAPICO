# TPO 포함 여부 의사결정안

## 결론

TPO는 PRD에 포함하는 것이 좋습니다. 다만 MVP에서는 **TPO 전용 모델 학습**이 아니라 사용자가 선택한 구조화 입력과 룰 기반 점수로 구현하는 것을 권장합니다.

추구미는 “어떤 분위기를 원하는가”, TPO는 “어디서 무엇을 하는가”이므로 서로 대체되지 않습니다. 두 축을 분리하면 제품 가치가 선명해지고 학습 범위도 통제할 수 있습니다.

## 별도 학습이 필수는 아닌 이유

별도 학습이 필요한 경우는 사진이나 캘린더 문장에서 TPO를 자동 추론하거나, 충분한 사용자 선택 데이터로 개인화 랭킹 모델을 만들 때입니다. MVP는 사용자가 TPO를 직접 선택하고 의류 속성·카테고리·노출도·격식도를 규칙으로 평가하면 됩니다.

다음처럼 `5개 추구미 × 5개 TPO = 25개 클래스`를 만들지 않습니다.

```text
최종 점수 = 날씨 적합성 + 추구미 적합도 + TPO 적합도 + 색상/조합 점수
```

- 날씨: 부적합 아이템을 우선 제거하는 hard constraint
- 추구미: 이미지 임베딩 또는 태그 기반 점수
- TPO: 룰·속성 매트릭스 기반 점수
- 사용자 행동 데이터가 쌓이면 각 가중치만 학습

## MVP TPO 권장안

### 입력

홈에서 오늘의 상황을 하나 선택합니다.

1. 일상·등교
2. 출근·비즈니스
3. 데이트·모임
4. 격식·행사
5. 야외·활동

초기에는 직접 선택만 지원하고 캘린더 자동 분석은 제외합니다. TPO 미선택 시 `일상·등교` 또는 사용자의 최근 기본값을 사용합니다.

### 의류에 필요한 최소 속성

- category / subcategory
- formality: casual ↔ formal
- activity: low ↔ high
- exposure 또는 보온 수준
- color / pattern
- aesthetic scores

일부 속성은 자동 태깅하되 사용자가 수정할 수 있어야 합니다.

### 추천 결과 설명

설명에는 적용한 축을 분리해서 보여줍니다.

> 비 예보로 미끄러운 신발을 제외했고, 데이트 TPO에 맞춰 단정한 실루엣을 우선했어요. 선택한 추구미와 가까운 색상 조합으로 구성했습니다.

## PRD 반영 문구 제안

> 사용자는 추천 요청 시 오늘의 TPO를 프리셋에서 선택할 수 있다. 추천 엔진은 날씨 부적합 아이템을 제거한 뒤, 선택한 추구미 적합도와 TPO 적합도를 독립적으로 계산해 코디 3종을 생성한다. MVP에서는 TPO를 규칙 기반으로 반영하며 캘린더 자동 추론과 TPO 전용 학습 모델은 후속 범위로 둔다.

## 사용자 1차 검토용 전달문 초안

> 아직 팀 질문 문서로 확정하지 않은 초안입니다. 사용자 검토 후 전달본을 분리합니다.

```text
TPO는 PRD에 넣되, MVP에서 TPO용 모델을 별도로 학습하는 방식은 제외하는 안을 제안합니다.

추구미는 원하는 무드, TPO는 오늘의 상황이라 서로 다른 축입니다. 사용자가 홈에서 일상/출근/데이트/격식/야외 중 하나를 고르면, 추천 엔진이 날씨 조건으로 먼저 후보를 거른 뒤 추구미 점수와 TPO 룰 점수를 각각 계산하는 방식입니다. 따라서 5개 추구미와 TPO 조합을 전부 새 클래스로 학습할 필요는 없습니다.

캘린더 자동 분석과 행동 데이터 기반 TPO 개인화는 후속 범위로 두려고 합니다. 아래 세 가지에 의견 부탁드립니다.
1) TPO를 MVP 필수 기능으로 넣을지
2) 위 5개 프리셋 구성이 적절한지
3) 캘린더 자동 연동은 후순위로 두어도 되는지
```
