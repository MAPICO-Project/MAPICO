# 백엔드 작업기간 로드맵

> 일반 기술 스택 기준의 1차 산정입니다. Supabase·Vercel 확정 후 보정한 최신안은 `BACKEND_ROADMAP_SUPABASE_VERCEL_2026-09-27.md`를 사용합니다.

## 산정 기준

- 백엔드 개발자 1명, 주 5일 기준
- 목표: 서비스형 MVP(M1), 5개 추구미와 수동 TPO 포함
- AI 서버는 합의된 요청/응답 계약을 제공한다고 가정
- Frontend와 AI 개발은 병행
- 전체 댓글·팔로우·신고·추천 피드 랭킹과 캘린더 자동 분석은 제외
- 기간은 개발과 기본 테스트를 포함하며 모델 학습 기간은 제외

## 권장 일정: 8주 + 1주 버퍼

| 주차 | 백엔드 작업 | 완료 기준 | 예상 |
|---|---|---|---:|
| 사전 2~3일 | 범위 고정, ERD, API/AI 계약, 상태코드 | FE·AI가 같은 스키마 승인 | 2~3일 |
| 1주차 | 프로젝트 기반, DB, 인증, 사용자 프로필, 5개 추구미/TPO 설정 | 로그인 후 설정 저장·조회 | 5일 |
| 2주차 | 이미지 업로드, Pre-signed URL, GarmentBatch/Draft/Item | 원본 업로드와 분석 Job 생성 | 5일 |
| 3주차 | 비동기 AI 중계, 상태 조회, 부분 실패·재시도, 일괄 확정 | 검출 결과 수정 후 옷장 저장 | 5일 |
| 4주차 | 옷장 CRUD·검색·필터, 파생 이미지, 삭제 전파 | 사용자별 옷장 완결 | 4~5일 |
| 5주차 | 기상청 API, 좌표 변환, 캐시, WeatherSnapshot | 위치별 날씨 정규화·장애 폴백 | 5일 |
| 6주차 | 추천 요청, 날씨 필터, 추구미/TPO 점수 입력, 추천 3종 저장 | 같은 입력의 재현 가능한 추천 응답 | 5일 |
| 7주차 | OOTD 확정·캘린더, 기본 공개 게시·스크랩, 샘플 Mimic API | 추천→기록→조회 흐름 완성 | 5일 |
| 8주차 | 통합 테스트, 권한·보안, 로깅, 속도 개선, 배포 | 데모 시나리오와 회귀 테스트 통과 | 5일 |
| 버퍼 | 외부 API·AI 지연, 앱 연동 수정, 배포 이슈 | 미결함 정리 | 3~5일 |

총량은 약 **39~43 인일**, 캘린더 기준 **8~9주**입니다.

## 범위별 예상 기간

| 범위 | 포함 | 1인 예상 |
|---|---|---:|
| M0 데모 | 최소 사용자, 업로드/분석, 옷장, 날씨/TPO 추천 | 4~5주 |
| M1 서비스형 MVP | 인증, 저장, 캘린더, 기본 게시·스크랩, 배포 | 8~9주 |
| 전체 PRD | 댓글·좋아요·신고, 실제 피드, 벡터 검색, 스케줄링·알림 | 11~14주 |

백엔드 2명이 파일과 도메인을 나눠 병렬 작업하면 M1은 약 5~6주로 줄일 수 있지만, ERD/API 계약과 통합 담당자가 선행되어야 합니다.

## 백엔드 선행 의사결정

1. M0 또는 M1 중 제출 범위
2. 플랫폼과 인증 방식
3. 추구미 5개와 TPO 프리셋
4. AI Job의 동기/비동기 방식과 결과 스키마
5. 원본·누끼 이미지 보존 및 삭제 정책
6. 소셜 공개 범위와 신고/차단 필요 여부
7. 오전 7시 추천이 필수인지 요청 시 생성으로 시작할지

## 권장 마일스톤

- Milestone A: 이미지 한 장이 옷장 아이템으로 확정됨
- Milestone B: 실제 날씨와 TPO로 코디 3종이 생성됨
- Milestone C: 확정 코디가 OOTD 캘린더에 남음
- Milestone D: 샘플 피드 OOTD를 내 옷장으로 치환함

각 마일스톤을 독립 데모 가능하게 유지하면 AI나 소셜 범위가 지연돼도 핵심 결과물을 보존할 수 있습니다.
