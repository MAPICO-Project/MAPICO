# 학습 데이터 관리

## 현재 후보

| 데이터 | 목적 | 상태 | 확인할 사항 |
|---|---|---|---|
| DeepFashion 계열 | 카테고리·속성·표현 베이스라인 | 후보 | 사용할 세부 데이터셋, 라이선스, 클래스 매핑 |
| 팀 자체 Multi-item Flat Lay | 검출·분할·실제 도메인 평가 | 필수 | 2~6벌, 겹침·배경·조명 시나리오와 동의 |
| 사용자 수정 데이터 | 파인튜닝·오류 분석 | 장기 후보 | 동의, 삭제권, 품질 검수, 편향 |
| OOTD/추구미 무드보드 | 15대 추구미 정의와 임베딩 평가 | 필요 | 이미지 권리, 태그 일관성, 유사 카테고리 경계 |

## MVP 라벨 초안

- `top`
- `bottom`
- `outerwear`
- `shoes`

검출·저장용 대분류에는 `accessory`와 `other/ignore` 정책이 추가로 필요합니다. 세부 카테고리와 패턴은 데이터 품질과 일정 확인 후 확장하며, 대표 색상은 별도 추출 파이프라인으로 시작합니다.

## 필요한 평가셋

- Single-item set: 속성·분류 모델 자체 성능
- Multi-item Flat Lay set: 검출·분할·end-to-end 등록 성능
- Aesthetic pair/ranking set: 특정 추구미와의 상대적 적합성 평가
- Outfit compatibility set: 날씨·TPO·추구미별 조합 선호
- Mimic set: 원 OOTD 아이템별 허용 가능한 대체 아이템

## 외부 데이터 편입 절차

1. 원 배포처에서 라이선스와 이용 조건을 확인합니다.
2. 원 클래스에서 프로젝트 클래스까지의 매핑표를 작성합니다.
3. 중복·손상 파일·라벨 누락을 검사합니다.
4. 동일 상품, 촬영 세션, 사용자 단위 누수를 막아 split을 만듭니다.
5. 클래스별 표본을 육안 검수합니다.
6. 출처·버전·해시·변환 스크립트를 기록합니다.
7. 실제 촬영 골든셋과 분리된 상태로 학습에 편입합니다.

## 회의에서 결정할 데이터 질문

- DeepFashion의 어느 하위 데이터셋을 사용할 것인가?
- 4개 대분류의 경계와 원피스·가방·액세서리 처리 방식은 무엇인가?
- 팀 자체 촬영은 사람 착용 사진인가, 바닥/행거 제품 사진인가?
- 사용자 이미지의 학습 재사용 동의를 MVP에 포함할 것인가?
- 색상 정답은 단일 대표색인가, 주색/보조색인가?
- 15대 추구미의 정확한 목록과 정의·중복 허용 기준은 무엇인가?
- 옷끼리 겹쳐 놓는 촬영을 허용할 것인가, 분리 배치를 강제할 것인가?
