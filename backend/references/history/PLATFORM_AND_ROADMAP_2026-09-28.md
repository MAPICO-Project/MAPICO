# 마피코 플랫폼 판단과 병렬 일정 제안

## 앱인가 웹인가

현재 PRD의 '앱 실행', 카메라, 바텀 내비게이션은 UX 표현이다. 네이티브 앱 구현 플랫폼(React Native/Flutter/네이티브 SDK), 앱스토어 출시, 백그라운드 위치 권한은 확정된 바 없다. Vercel/Supabase 선택은 서버 배포 선택이지 클라이언트가 웹이라는 증거는 아니다.

따라서 **제품 플랫폼은 미확정**, 이번 실행 범위는 **모바일 웹 클라이언트를 연결할 수 있는 HTTP 백엔드 임시 배포**로 기록한다. 반응형 웹을 먼저 구현하고 PWA는 별도 검증하는 방향을 제안한다. 설치형 네이티브 앱은 팀 결정 후 추가한다. 현재 배포 안내 페이지를 제품 프론트엔드로 부르지 않는다.

## 병렬 원칙

- FE는 최종 디자인 완성을 기다리지 않고 기능별 와이어·API 예제로 화면을 연결한다.
- BE는 최신 데이터 모델과 API 계약을 먼저 맞추고 기능 단위로 스테이징에 배포한다.
- AI는 5종 스타일 정의·평가셋·분류 가능 속성을 확인하고 Worker 입출력 계약부터 제공한다.
- PM은 TPO·추천 시간·OOTD 정책 등 충돌을 결정 로그에 반영한다.
- 스텁·샘플 응답과 실제 AI/DB 응답을 표시로 구분한다.

## 기술 피드백

- 코디 보관함은 날짜와 무관한 재사용 가능한 조합, OOTD는 특정 날짜의 착용 사실/계획과 스냅샷이다. 별도 엔티티가 필요하다.
- 과거/미래 날짜에 오늘의 날씨를 붙이면 잘못된 기록이 된다. 대상 시각·예보/관측 구분·자료 없음 정책을 정해야 한다.
- 색상/추구미를 화면에서 숨기는 것과 AI 내부 특징을 제거하는 것은 다른 결정이다.
- TPO 제거가 확정되기 전 기본 TPO를 조용히 적용하지 않는다.
- 매일 5시와 7시, 목표 3개와 1~3개 문구를 하나로 정리해야 한다.
- 공개 피드는 게시자의 비공개 원본/옷장 전체를 노출하지 않아야 한다. 신고·삭제·게시 취소·회원탈퇴 정책도 최소 정의한다.
- 0% 매칭은 모델 점수 0과 후보 없음이 다르다. 점수 보정 전 '매칭률'을 객관적 정확도처럼 표시하지 않는다.
