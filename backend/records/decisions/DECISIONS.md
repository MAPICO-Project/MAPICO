# 의사결정 기록

## 2026-09-29 엄격한 MVP·백엔드 우선 결정 (최우선)

- **MVP 범위:** 현재 정본 ERD의 22개 public 테이블과 연결 도메인을 MVP에서 모두 구현·검증한다. 테이블 생성만으로 완료하지 않고 사용자 흐름·내부 job·권한·테스트에서 실제 사용해야 한다.
- **API 실행 기준:** 현재 OpenAPI 50개 operation은 별도 계약 변경으로 제외하지 않는 한 MVP 구현 대상으로 관리한다. 구현 증거 없이 설계만으로 완료 처리하지 않는다.
- **개발 전략:** Backend Preview와 개발용 Supabase를 먼저 준비해 Frontend와 AI가 독립적으로 계약·통합 테스트할 수 있게 한다. 로컬 구현과 사용자 원격 설정을 병렬 진행한다.
- **품질 기준:** AI가 포함된 MVP이므로 fixture·샘플·실제 추론을 구분하고, 모델 실패 fallback, 버전, 평가, 개인정보·삭제 경계를 포함한다.
- **다이어그램:** 로컬 Mermaid를 검토 가능한 정본으로 유지한다. MCP 협업 도구는 네이티브 보드 편집에 사용하되 보드만의 변경은 PRD/결정 기록에 반영되기 전까지 확정으로 보지 않는다.
- **미결 정책 보존:** TPO, 하루 OOTD 수, `wear_status`, 추천 생성 시각, 최종 taxonomy 명칭은 이 결정으로 자동 확정하지 않는다.
- 정본 실행 문서: [통합 로드맵](../../deliverables/product/ROADMAP.md), [사용자·에이전트 실행계획](../../worklogs/2026-09-29_USER_AGENT_EXECUTION_PLAN.md).

## 플랫폼 출처 정정 및 사용자 재확인 질문 (아래 기록보다 우선)

- **결정 출처:** 사용자 채팅의 "모바일 웹으로 우선해보는 것으로 가시죠". 팀 회의 결론으로 인용하지 않는다.
- **회의 근거 확인:** 로컬 `records/meetings/2026-09-26.md`를 전체 확인했으며 모바일 웹·네이티브·PWA 등 플랫폼 선정 내용은 없다. 이 파일은 통화 정리본으로 원문 전사가 아니므로 회의 원문 전체를 확인했다고 주장하지 않는다.
- **의미:** 모바일 웹은 모바일 브라우저에 최적화한 웹이다. 네이티브 앱, 스토어 배포, PWA 설치·오프라인 기능까지 승인된 것은 아니다.
- **선정 이유의 지위:** 링크로 공유·검증하기 쉬운 초기 웹 배포 및 FE/BE 연동을 고려한 개발 측 제안이다. 해당 이유가 회의에서 합의됐다고 기록하지 않는다.
- **현재 상태:** 사용자가 회의 근거와 모바일 웹의 의미·이유를 재확인 중이다. 변경 지시는 없으므로 기존 우선 진행 방향을 임의로 취소하거나 네이티브로 변경하지 않는다. 아래 '확정'은 과거 사용자 채팅 지시 이력이며 팀 전체 플랫폼 합의를 의미하지 않는다.
- 이번 변경은 PRD·결정 기록의 출처 정정뿐이며 코드·SQL·원격 환경은 변경하지 않았다.

- Vercel 등 배포 프로젝트는 각 파트 폴더를 Root Directory로 설정하고, 비밀값과 원격 Supabase 상태는 Git으로 이전하지 않습니다.

## 2026-10-02 루트 구조 단순화

- 저장소 루트의 추적 항목은 `README.md`와 `backend/`만 유지합니다.
- 루트 README는 특정 파트의 작업 보고가 아니라 프로젝트 목적, 핵심 사용자 흐름, 전체 기능과 파트별 상태를 설명합니다.
- 백엔드 실행·API·DB·환경변수·검증 정보는 `backend/README.md`에서 별도로 관리합니다.
- 기존 제품 근거, 설계, 작업 기록과 참고자료는 현재 구현 주체인 `backend/` 아래로 모읍니다.
- 프론트엔드·AI·디자인 팀의 최상위 폴더 이름과 내부 구조를 미리 만들거나 강제하지 않습니다. 각 파트가 작업을 시작할 때 필요한 구조를 직접 추가합니다.
- 루트 단순화를 위해 기존 GitHub Actions 파일은 제거합니다. 자동 CI가 다시 필요하면 팀 합의 후 원하는 형태로 추가합니다.
