# 2026-10-09 유저플로우 검토

## 요약

- **무엇을**: PM 겸 프론트의 Canva 유저플로우([원본](https://www.canva.com/design/DAHW1gVlGD4/2IqavaVEc6wZIxsb_uNvGA/view))를 [USER_FLOWS](../docs/design/USER_FLOWS.md) 정본으로 옮기고, 확정 사항을 [PRD](../docs/product/PRD.md)·[DECISIONS](../records/decisions/DECISIONS.md)·[README](../../README.md)에 반영했다. 영문명 MAFICO, 모바일 앱 확정.
- **왜**: 사용자가 2026-10-09 이 플로우를 UX 기준으로 확정했다. 이전 문서의 추구미 이름 미정·모바일 웹 우선과 충돌했다.
- **검증**: 담당 문서의 상대 링크가 실제 파일로 열리는지 확인했다. 플로우 텍스트는 추출본과 대조해 조건·수치를 그대로 옮겼다.
- **미검증**: 텍스트는 Canva 페이지에서 브라우저로 추출했다. 도형 배치·화살표 연결은 눈으로 대조하지 않았다. DB·API 격차(아래)는 아직 고치지 않았고, migration은 실제 DB에 push하기 전이다.

## 플로우 내부 빈틈

- 홈 추구미 Chip은 보조 **1~2**, 온보딩 결과·마이페이지 추구미 관리는 보조 **0~2**로 서로 다르다. 보조가 0개인 사용자의 홈 Chip 구성이 정해지지 않았다.
- 홈 '옷장 아이템 충분한가?'의 기준(개수·카테고리 조합)이 정의되지 않았다.
- 추천 코디가 3개 미만으로 만들어질 때의 처리가 없다.
- 오류·빈 상태 경로가 없다: 위치 권한 거절, 날씨 조회 실패, 네트워크 오류, 추천 생성 실패, 피드 0건, 빈 코디 보관함, 빈 캘린더.
- 신규 유저는 원샷 안내(실제 등록 없음) 후 빈 옷장으로 홈에 들어가므로 첫 화면이 항상 '추천 불가' 상태가 된다.
- 무드보드 예외: 3장 미만 선택 후 이탈·진행 처리, 보조 추구미 선정 시 차순위 동점 처리가 없다(Tie-break는 '동점?' 하나로만 표시).
- 따라입기는 전체 매칭률 0%만 분기한다. 낮은 매칭률 기준이 없고, 유사도 점수를 %로 노출하는 것이 적절한지 정해지지 않았다.
- 카카오 로그인 실패·취소 경로가 없다.
- 홈 '오늘 입기' 시 같은 날짜에 이미 OOTD 기록이 있을 때의 충돌 처리가 없다.
- 피드 포스트 신고·사용자 차단 경로가 없다.

## PM에게 확인할 질문

1. TPO는 기능에서 완전히 제외한 것인가? (플로우에 TPO가 없다)
2. 하루 OOTD는 1건인가? 계획(planned)과 실제 착용(worn)을 구분하는가? 착장 사진은 선택인가 필수인가?
3. 위치 권한 거절·날씨 조회 실패 시 홈에 무엇을 보여주는가?
4. '옷장 아이템 충분'의 기준은? 추천이 3개 미만이면 어떻게 보여주는가? 홈 보조 Chip은 1~2와 0~2 중 무엇이 맞는가?
5. 회원 탈퇴 시 공개 게시물·업로드 이미지·AI 파생 데이터(벡터·분석 결과)·타인이 누른 좋아요는 어떻게 처리하는가?
6. 따라입기 매칭률을 %로 그대로 노출하는가? 낮은 매칭으로 볼 기준이 있는가?

## DB·API 대조 결과

migration(`supabase/migrations/`)과 `docs/openapi.yaml` 기준. 실제 DB에 push하기 전이라 지금 고치는 비용이 가장 낮다.

| 플로우 항목 | 현황 | 판정 |
|---|---|---|
| 추구미 5종 | seed 5개, 코드 일치 | 지원 |
| 메인 1 + 보조 0~2 | weight만 저장, 메인/보조 역할 없음(동점 시 메인 불명) | 부분 → migration |
| 무드보드 카드·점수·tie-break | 카드 테이블·API 없음 | 없음 (클라이언트 계산이면 불필요) |
| 옷 카테고리 6종 | DB는 dress·other 포함 8종 | 충돌 → migration |
| 홈 추구미 Chip 선택 | 추천 요청이 location·tpo만 받음 | 없음 → API |
| 옷장 충분 판정 | shortfall 코드 있음, 기준 문서 없음 | 부분 |
| OOTD 선택 사진 | 컬럼·테이블 없음 | 없음 → migration |
| 통계 '최다 추구미' | OOTD에 추구미가 없어 계산 근거 없음 | 없음 → 원천 결정 필요 |
| 피드 날씨 '바람' | weather enum에 wind 없음 | 충돌 → migration |
| 포스트 연결 아이템 최소 1개 | post↔garment 테이블 없음 | 없음 → migration |
| 따라입기 | 대표 이미지를 다시 분석하는 구조. 플로우는 연결 아이템 ID↔벡터 매칭 | 충돌 → 재설계 |
| 프로필 이미지 | avatar 컬럼 없음, API 422 | 없음 → migration |
| 회원 탈퇴 | DELETE /me 미구현, Storage 정리 없음 | 부분 |

지원 확인: 비고·원본·누끼, 추천 3개·이유, 코디 보관함, OOTD 별점·메모·날씨·하루 1개, 통계 Top3·30일 미착용, 좋아요·내 포스트 수정/삭제, 닉네임.
플로우에 없는 백엔드 기능: TPO, 의류 formality·color·pattern·subcategory, 의류 추구미 자동 점수(플로우는 '자동 태그 없음'), OOTD planned/worn, 포스트 초안 상태.

**push 전 고칠 것(우선순위)**
1. 포스트↔옷 연결 테이블(최소 1개) + 따라입기를 연결 아이템 기준으로 재설계
2. 추구미 메인/보조 역할 컬럼(메인 정확히 1개)
3. 날씨 enum에 wind 추가, 카테고리 6종 정리(dress·other 처리)
4. OOTD 사진 저장 구조
5. 프로필 이미지 컬럼, '최다 추구미' 계산 원천
