## 계약 문제 기록 (백엔드 세션에 넘김, 10-11 전달)
1. **CORS**: `lib/cors.js` preflight `Access-Control-Allow-Headers`가 `Authorization, Content-Type`뿐 → `Idempotency-Key`를 쓰는 브라우저 POST가 모두 막힘. dev 서버에서만 헤더를 덧붙여 우회.
2. **cutout owner**: callback은 cutout `storage.objects.owner_id` = job 사용자를 요구(`get_analysis_cutout_fence`, `apply_analysis_result`). 서버 키 업로드는 owner가 비어 실제 worker가 만족할 방법이 없음. 가짜 worker는 DB pooler로 owner를 직접 기록(데모 전용).
3. **날씨 제공자**: 백엔드는 정규화 JSON을 주는 HTTPS 어댑터(`X-API-Key`)를 전제. `_key`의 KMA(data.go.kr)는 형식이 달라 그대로 못 씀 → 배포에 어댑터 필요. dev 서버가 KMA 초단기실황 어댑터를 내장.
4. **job claim 범위**: `claim_analysis_job`은 공용 DB의 모든 사용자 job을 가져감(worker 여러 개면 서로 가로챔). 참고.
5. **hosted column grant 누락**: `GET /feed`·`/me/posts`가 `feed_posts.deleted_at`으로 필터하나 grant(202609280001:90)에 없음, `GET /analysis-jobs/{id}`가 `analysis_jobs.max_attempts`를 select하나 grant에 없음 → PostgREST 403 42501 → 503 `DATABASE_SCHEMA_NOT_READY`. PGlite 테스트로는 안 잡힘.
6. **버그**: `lib/feed.js` listResponse `if (rows.error) return rows;` → `rows.error`여야 함(현재 status undefined → 500).
7. **callback 503 원인**: hosted `storage.objects.owner_id`는 text인데 `get_analysis_cutout_fence`(202610010001:223)·`apply_analysis_result`(202610090002:231)가 uuid와 비교 → 42883 `text = uuid` → 503 `SUPABASE_UNAVAILABLE`. PGlite 스텁(`scripts/validate-schema.mjs`)은 owner_id가 uuid라 안 잡힘. hosted에서 AI 분석 완료가 불가능.
9. **날씨 항상 503**: `lib/weather.js` snapshot()이 `row.valid_at !== slot`을 문자열로 비교(PostgREST `…+00:00` vs `toISOString()` `…000Z`) → 저장 성공 후에도 null → 503 `WEATHER_UNAVAILABLE`, 캐시도 항상 miss. 추천도 같은 경로라 홈 추천이 막힘.
8. **날씨 스냅샷 조회 API 없음**: 캘린더·OOTD는 `weather_snapshot_id`만 주므로 "저장 당시 날씨 아이콘"(유저플로우 §4)을 그릴 수 없음.
10. (질문) OOTD 사진 해제: `PATCH /ootd`에서 붙인 사진을 떼는 방법이 계약에 없음(교체만 가능).
11. (질문) OOTD→피드 공유: 사진 없는 OOTD는 공개할 수 없어 갤러리 사진을 따로 골라야 함. 서버 측 "OOTD 사진을 피드로 복사"가 없어 앱이 signed URL에서 받아 다시 올림.
12. (질문) `DELETE /feed/{id}`만 Idempotency-Key가 없음(`/garments`·`/ootd` 삭제와 다름).
- 원격 DB 데모 계정: `new@`·`demo@`·`friend@mafico.dev`(비밀번호는 저장소에 두지 않음). 백엔드 hosted 실측 중에는 시드를 멈춘다.
