# MyFit:Core 설계 검토

검토 기준: 로컬 `PROJECT_PROPOSAL.md`, `DECISIONS.md`, 2026-09-27 API·일정 초안과 사용자가 전달한 회의 내용. 최신 Notion 본문을 직접 확인한 결과로 해석하지 않습니다. 담당: 병렬 Astra 검토 트랙.

## 판단

ERD, 유스케이스, 등록·추천 시퀀스는 지금 필요합니다. AI 구현이 끝나기 전에도 사용자 소유권, 분석 결과 확정, 추천 선택과 기록의 관계를 정할 수 있습니다. 구체적인 모델별 GPU 토폴로지, 벡터 차원, 실제 소셜 피드 운영 설계는 실험·범위 확정 후 보완합니다.

Supabase 연결만으로 AI 기능과 Vercel API가 동작하지는 않습니다. DB migration은 저장·제약·접근제어를 준비하며, API 설계서는 이후 구현할 서버의 계약입니다. GPU worker와 비동기 작업 소비, 파일 정리, 날씨 연동은 별도 구현 대상입니다.

## 일정 산정 정정

이전 `BACKEND_ROADMAP_SUPABASE_VERCEL_2026-09-27.md`의 단계별 숫자를 그대로 더하면 다음과 같습니다.

`(2~3)+(3~4)+(4~5)+5+4+(3~4)+(4~5)+(4~5)+(4~5) = 33~40인일`

따라서 표에 적힌 32~37인일과 일치하지 않습니다. 1인·주 5일 기준 **6.6~8주**, 버퍼 5일 포함 **7.6~9주**가 해당 상세 표의 산술적 합계입니다. 이는 M1에 대한 기존 항목 합계이며 M0.5의 확정 견적이 아닙니다. AI 모델 개발 시간, FE 개발 시간, 계정 심사 대기는 별도로 봅니다. 2인 투입도 연동·검증의 의존성이 있어 단순히 절반으로 줄이지 않습니다.

설계 산출물 완성이 실제 API·인증·큐·worker 연동 완료를 뜻하지 않으므로, 설계 작업만큼 전체 일정을 자동 차감하지 않습니다.

## 구현 전 확인할 수용 조건

- 사용자 A가 사용자 B의 의류·이미지·분석 결과를 조회하거나 자기 코디에 연결할 수 없어야 함.
- 동일 배치 확정·오늘 입기 재요청이 의류나 기록을 중복 생성하지 않아야 함.
- 재시도 전 callback이 최신 시도의 결과나 사용자 수정값을 덮어쓰지 않아야 함.
- 업로드 완료는 클라이언트의 완료 주장만으로 승인하지 않고 객체 존재·소유 경로·허용 파일 조건을 서버가 확인해야 함.
- 날씨 조회 실패, 위치 미제공, 옷 부족을 화면이 구분 가능한 응답으로 처리해야 함.
- 인증 없는 호출과 로그인한 사용자의 직접 DB 호출 모두 접근 권한 테스트 대상임.
- SQL 정적 파싱, 실제 PostgreSQL 적용, JWT/RLS 검증, 외부 배포는 서로 다른 검증 단계로 기록해야 함.

## SQL 초안 교차 검토

`202609270001_core.sql`과 `202609270002_transactions.sql`의 작성 중 버전을 확인했습니다. 사용자 소유권 복합 FK, 서버 쓰기 전용 테이블, 비공개 Storage, 배치 확정과 오늘 입기의 트랜잭션 함수가 설계에 포함됐습니다. 동일 사용자라도 다른 배치의 Job을 연결할 수 있던 부분은 `(user_id, batch_id, job_id)` FK로 보강됐습니다.

추가로 NULL lease 시간·시도 번호 처리, 실패 callback 재전송의 멱등성, 부분 성공 후 재시도의 기존 draft 충돌을 작성 담당자에게 전달했습니다. 부분 성공 결과를 수정한 뒤 전체 재분석하면 사용자 수정값 보존 문제가 생기므로, 첫 구현에서는 완전 실패만 재시도 대상으로 두는 것이 적절합니다.

이 절은 정적 교차 검토 기록이며 실제 Supabase 실행·배포 검증 결과가 아닙니다. 하루 OOTD 한 건과 원본 draft를 거친 의류 등록은 현재 DB의 제약이므로 화면·API도 같은 범위를 설명해야 합니다.

## 팀에 전달할 피드백

TPO를 추가한다고 별도 분류 모델 학습이 필수는 아닙니다. ‘격식도·활동성’ 같은 의류 속성을 사용해 프리셋별 규칙 점수를 계산할 수 있습니다. 다만 속성의 정답 데이터와 기본값이 없으면 룰도 임의적이므로, 사람이 검토한 소수 코디로 먼저 적합성을 평가하는 편이 좋습니다.

‘2초·90%’는 현재 검증 전 목표입니다. 업로드 포함 여부, 장비, 이미지 해상도, 6벌 조건, p95 지연시간과 검출·분할·분류 지표를 나눠 승인 조건을 작성해야 합니다. ‘매칭률 95%’ 역시 실제 확률처럼 표시하지 말고 점수의 정의와 검증 방식을 먼저 정해야 합니다.

남은 제품 결정은 5개 추구미 목록, TPO 미선택 UX, 이번 제출에 필요한 샘플 피드·Mimic 범위, 팀 인력·마감일입니다. 사용자의 1차 검토를 거친 뒤 팀 질문서로 확정합니다.
