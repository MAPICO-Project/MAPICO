# 실습 안내 및 AI 설계 정리

## 반영 내용

- 사용자가 Vercel/Supabase를 직접 실습할 수 있도록 DEPLOYMENT_LAB.md 작성.
- 아키텍처 분리는 역할/계약을 나누는 것이라고 설명하고 현재 목표·후속 의류 도메인 확장 다이어그램 작성.
- 추구미 개수 5종만 확정, 명칭은 후속 선정. 후보 예시를 최종 목록으로 취급하지 않음.
- 전체 요구사항과 실제 MVP 선정 구분. 데이터 수집에서 이미지 단위 스타일 분류도 라벨링임을 명확히 함.
- Figma 본문은 아직 열람하지 못했으며 디자인 일치 여부를 주장하지 않음.

## 무료 배포 검토

- Vercel Hobby에서 조직 private 저장소는 지원되지 않음. 공개 조직 저장소 경로를 검토하며 비상업적 용도 및 GitHub 연결 조건도 충족해야 함.
- 현재 저장소 공개 전환, 요금제 변경, 배포, 원격 DB SQL 적용은 이번 작업에서 하지 않음.
- Supabase 데이터 읽기 URL/key 설정과 SQL 스키마 관리는 서로 다른 연결임.
- 현재 backend는 일부 진단/카탈로그 endpoint만 구현. 모든 제품 API가 구현되거나 원격 DB 마이그레이션이 끝났다는 뜻이 아님.

## 병렬 작업

- astra_review: 무료 배포 조건 공식 문서 검토 후 별도 보고서 작성 요청.
- schema_current: PRD/결정 기록의 최신 추구미 상태 정합성 수정 요청.
- root: 실습 안내, AI 아키텍처, 데이터 계획, 인덱스 및 검증 담당.

## 검증

- node scripts/validate_diagrams.mjs 성공: ERD 1개, 사용자 흐름 4개, AI 아키텍처 2개 Mermaid 구문 검증.
- SQL/code 모델이나 기존 마이그레이션의 추구미 seed는 이번 문서 작업에서 바꾸지 않음. 이전 명칭은 임시 샘플이며 새 최종 분류 확정 후 별도 버전 변경 필요.
