# 2026-10-09 플로우 데모 앱 계획 (새 세션 인계용)

## 목적
- 팀원(프론트·AI)에게 **백엔드가 유저플로우대로 어떻게 동작하는지** 보여 주는 동작 예시 앱이다. 제품 디자인이 아니다. 디자인·최종 화면은 프론트 팀이 만든다.
- 플로우([USER_FLOWS](../docs/design/USER_FLOWS.md))보다 더 자세하게 우리가 고려한 처리(아래 '상세 처리')를 실제로 구현해 보여 준다. 프론트는 화면 상태·오류 처리를, AI 팀은 분석 요청·콜백 형태를 이 앱에서 참고한다.

## 범위
- 위치: 저장소 최상위 `demo-app/`(새 폴더). 추가하면 루트 `CLAUDE.md` 코드 지도 표에 한 줄 적는다. README에 "데모용, 제품 코드 아님"을 명시한다.
- 스택: Flutter + `supabase_flutter` + `flutter_riverpod` + `go_router` + `image_picker`. 이전 프로젝트와 같은 조합이라 구조를 참고할 수 있다.
- 화면: GNB 4탭(홈 / 디지털 옷장 / 스타일 믹스·캘린더 / 소셜 피드) + 마이페이지(홈 프로필 아이콘). 기본 Material 위젯만 쓴다.
- API는 `backend/docs/openapi.yaml` 계약 그대로 호출한다. 앱 안에서 계약을 바꾸지 않는다. 계약과 안 맞는 점은 이 문서 아래에 기록하고 백엔드 세션에 넘긴다.

## 시작 전에 필요한 것
1. **Flutter SDK 설치**: 이 PC에는 아직 없다(`flutter` 명령 없음). Android 에뮬레이터 또는 실기기도 필요하다.
2. **백엔드 접속 대상**: 원격 Supabase에 migration push(사용자 확인 후)와 Vercel preview 배포가 필요하다. 그 전에는 로컬 `vercel dev`로 붙는다.
3. **로그인**: 카카오 로그인은 카카오 개발자 앱과 Supabase Auth Kakao provider 설정이 필요하다. 그 전까지 데모는 Supabase 이메일 테스트 계정으로 로그인하고, 카카오 버튼은 "설정 필요" 상태로 둔다.
4. **AI 분석**: 실제 AI worker가 없다. 데모용 가짜 worker(HMAC 서명 콜백을 보내는 개발 스크립트)를 `backend/tools/`에 두고, 개발 환경에서만 쓴다.
5. **키**: `../_key/`에서 읽고 앱 코드·저장소에 넣지 않는다. 앱에는 Supabase URL과 publishable key만 넣는다(빌드 시 `--dart-define`).
