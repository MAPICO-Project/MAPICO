## 엄격한 MVP 실행 범위 — 2026-09-29 사용자 확정

- 전체 수직 흐름: 로그인/취향 선택 → 옷 등록·수정 → 날씨/취향 기반 추천 → 보관/OOTD → 피드/좋아요 → 따라입기.
- ERD의 22개 public 테이블은 모두 실제 흐름·내부 job·권한·테스트에서 사용한다. schema 생성만으로 MVP 완료로 보지 않는다.
- 현재 OpenAPI 50개 operation은 별도 계약 변경 전까지 구현 대상이다. 작은 수직 슬라이스로 순차 배포하되 최종 coverage에서 누락하지 않는다.
- 다중 촬영은 2~6벌의 비겹침 입력부터 검증하고, 실패 시 단건 등록·수동 카테고리 수정·명시적 재시도를 제공한다.
- 5종 추구미 분류 성능과 사용자 선택을 분리한다. 학습이 기대에 못 미쳐도 수동 선택·기본 추천·템플릿 설명으로 전체 흐름을 유지한다.
- 소셜·따라입기는 MVP에 포함한다. 남성용 별도 모델과 피드백 재학습은 현재 ERD 밖 후속 확장으로 유지한다.
- 세부 단계와 완료 gate는 [통합 로드맵](ROADMAP.md)을 따른다.

## '라벨링 안 해도 됨'의 정확한 범위

**'이 사진이 무슨 스타일인지 알려주는 것' 자체가 이미지 수준 라벨링이다.** 이번에는 박스·픽셀 마스크를 직접 그리는 정밀 라벨링을 피할 수 있다는 의미로 정리한다.

- 스타일 분류 학습: 이미지별 스타일 이름/code는 필요. 폴더 분류 또는 CSV로 제공 가능.
- zero-shot 사전학습 모델 baseline: 별도 학습 라벨 없이 추론할 수 있어도, 성능을 평가할 정답 라벨은 필요.
- 검출/분할: 사전학습 모델을 활용하면 직접 라벨링을 줄일 수 있다. 직접 해당 모델을 학습/평가하려면 박스·마스크 등 목적에 맞는 라벨이 별도로 필요할 수 있다.
- 착장 사진으로 학습한 모델이 옷 단품 누끼에도 잘 맞는다고 가정하지 않는다. input_kind를 구분한다.

## 수집 규칙 제안

1. 5개 스타일마다 한 문장 정의, 포함 예시, 제외/혼동 예시를 먼저 만든다.
2. Pinterest/Instagram/쇼핑몰은 탐색 후보이지 무조건 학습에 사용 가능한 데이터원이 아니다. 원본 출처·이용조건·허용 범위를 확인하고 불명확하면 학습에 편입하지 않는다. 이 문서 작성 중 크롤링/다운로드는 하지 않았다.
3. 직접 촬영하고 동의를 받은 데이터, 사용 조건이 명확한 데이터부터 우선 검토한다. 공개돼 있다는 사실만으로 재배포/학습 허용을 단정하지 않는다.
4. 폴더의 스타일명뿐 아니라 아래 최소 메타데이터를 기록한다. 사용자 핸들·불필요한 개인정보는 수집하지 않는다.
5. 한 브랜드/배경만 모으지 않고 출처·포즈·배경을 다양화한다. 검색엔진보다 플랫폼 이미지가 반드시 성능이 좋다는 것은 검증 전 가설이다.
6. 동일 상품/착장/연속 사진·중복 이미지는 묶어 학습/평가에 나뉘지 않게 한다. 각 스타일에 고정 평가셋을 먼저 확보한다.
7. 여러 스타일이 섞인 사진은 억지로 하나에 넣지 말고 ambiguous/review 상태로 둔다. 한 명이 수집하고 다른 팀원이 표본 검토하는 방식 권장.

권장 CSV 필드:

```text
image_id, source_url, original_source, usage_permission_note,
collector, style_code, taxonomy_version, input_kind,
style_domain, group_id, review_status, split
```

모델이 클래스 수만 맞춘다고 좋은 추천이 되는 것은 아니다. 라벨 일관성·누끼 사진과의 도메인 차이·실제 코디 만족도를 별도로 검증한다.

## 다음 인터뷰에서 먼저 정할 3가지

1. 5종은 서로 어떤 시각적 특징으로 구분하나요? 두 스타일에 모두 해당하면 어떻게 처리하나요?
2. 학습 입력은 착장 전체인가요, 옷 한 벌인가요? 최종 서비스 입력과 같은가요?
3. 시연에서 반드시 성공해야 할 사용자 흐름 하나는 무엇인가요? 그 흐름 밖의 기능은 후속으로 돌릴 수 있나요?
