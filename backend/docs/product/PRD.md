### 확정된 것 (유저플로우 2026-10-09)

- **이름**: 정식 이름 MAFICO(MyFit:Core 약칭), 한글 마피코.
- **플랫폼**: 모바일 앱으로 확정(사용자 확정, FCM 키 발급 완료). 이전의 "모바일 웹 우선"은 과거 진행 방향 이력이며 [의사결정 기록](../../records/decisions/DECISIONS.md)에 보존한다.
- **배포**(2026-10-09 사용자 결정): 앱스토어에 등록하지 않고 웹페이지에서 설치 파일을 내려받게 한다. 신고·차단은 스토어 등록 시점에 추가하며 그 전까지 없다.
- **푸시 알림**(2026-10-09 사용자 결정): FCM 키는 보관만 하고 MVP·현재 로드맵에 넣지 않는다. 날씨·오늘 입을 옷 알림은 여유가 생기면 추후 제안한다.
- **추구미 5종**: 페미닌·Y2K·미니멀·그런지·캐주얼. 사용자는 메인 1개 + 보조 0~2개를 가진다(온보딩·마이페이지 추구미 관리 기준).
- **온보딩 분기**: 카카오 소셜 로그인 → 신규 회원이면 "추구미를 알고 있는가?" → 직접 선택(메인 1 → 보조 0~2) 또는 무드보드 탐색 → 추구미 결과에서 직접 수정 또는 이대로 시작 → 원샷 옷장 등록 안내(예시 화면만, 실제 촬영·등록 없음) → 홈.
- **무드보드 규칙**: 카드 총 15~20장, 5개 추구미별 3~4장, 최소 3장·최대 6장 선택. 카드 1장마다 해당 추구미 +1(라벨 비노출). 최고 점수 = 메인, 차순위 = 보조. 추구미 간 유사도는 MVP에서 고려하지 않는다. 동점이면 Tie-break(대표 이미지 1~2장 중 더 선호하는 것 선택).
- **GNB**: 홈 / 디지털 옷장 / 스타일 믹스·캘린더 / 소셜 피드 4개. 마이페이지는 GNB에서 빼고 홈 우측 상단 프로필 아이콘으로 진입한다.
- **홈**: 현재 위치 날씨·기온, 추구미 Chip(기본 = 메인, 선택 시 Reload). 옷장 아이템이 충분하지 않으면 추천 대신 "옷장을 채우면 추천을 받을 수 있어요". 충분하면 AI 추천 코디 3개([1/3]~[3/3], 내 옷장 아이템 조합·선택 추구미·현재 날씨·AI 추천 이유)와 Reload. 행동은 코디 보관함에 저장 / 스타일 믹스 / 오늘 입기.
- **디지털 옷장**: 카테고리 전체·아우터·상의·하의·신발·가방·액세서리(저장 카테고리는 이 6종뿐, 2026-10-09 사용자 결정. AI가 6종 밖으로 분류하면 사용자가 6종 중 하나를 골라야 저장된다. 원피스 등 경계 옷의 배정 규칙은 정하지 않았다). 의류 상세는 누끼·원본·카테고리·비고이며 색상·추구미 자동 태그는 없다. 등록은 원샷 촬영(카메라 권한 없으면 설정으로 이동) 또는 앨범 → AI 분석(다중 검출·개별 분리·배경 제거·카테고리 분류) → 실패 시 다시 시도/이미지 재선택, 성공 시 결과 검토·카테고리 수정·비고 입력 → 모두 저장.
- **코디 보관함 vs OOTD 캘린더**: 코디 보관함 = 아직 입지 않아도 저장한 조합. OOTD 캘린더 = 특정 날짜에 실제로 입은 착장 기록. 코디 조합은 옷장 아이템 다중 선택(리스트/그리드) 방식이다.
- **OOTD 기록**: 날짜·날씨·착용 의류·별점 1~5·메모·선택 사진. 월별 캘린더에 썸네일 + 저장 당시 날씨 아이콘. 상세에서 피드 공유·수정·삭제(확인).
- **통계 3종**: 옷장 활용도 통계, 최다 추구미·아이템 Top 3, 30일 이상 미착용 아이템.
- **피드 필터**: 추구미(전체 + 5종), 날씨 5종(맑음·흐림·비·눈·바람). Masonry 그리드, Feed Reload.
- **포스트 작성**: 캘린더 OOTD에서 가져오기(사진/아이템/날씨 자동) 또는 갤러리 사진 + 착용 아이템 선택. 디지털 옷장 아이템 **최소 1개 연결 필수**(0개면 다음 버튼 비활성화). 입력: 대표 사진·연결 아이템·추구미·날씨/온도·캡션. 업로드 실패 시 입력 유지·다시 시도.
- **좋아요**: 좋아요하면 마이페이지 아카이브(좋아요한 코디)에 저장된다.
- **따라입기**: 포스트에 연결된 Item ID ↔ 내 옷장 Item Vector로 매칭하며 대표 이미지를 다시 객체 검출하지 않는다. 결과는 전체 매칭률·원본 ↔ 유사 아이템·아이템별 유사도 %이며 코디 보관함에 저장할 수 있다. 전체 매칭률 0%이면 "비슷한 옷이 없음, 옷장을 조금 더 채워보세요" → 옷 등록하기.
- **마이페이지**: 프로필 이미지 변경·닉네임 수정, 추구미 관리(메인 1 + 보조 0~2, 저장 시 추천 데이터 업데이트), 좋아요한 코디, 내가 올린 포스트(수정/삭제), 로그아웃, 회원 탈퇴(디지털 옷장·OOTD·사용자 데이터 삭제 안내 → 확인 → 계정 및 데이터 삭제).

## 2026-09-29 MVP 실행 범위 정정

- 사용자는 현재 정본 ERD의 전체 내용이 MVP에서 구현되어야 한다고 확정했다. 28개 public 테이블(2026-10-10 migration 기준)은 schema 존재뿐 아니라 제품 흐름·내부 job·권한·테스트에서 실제 사용되어야 한다.
- 현재 OpenAPI 53개 operation은 별도 계약 변경으로 제외하지 않는 한 MVP 구현 대상으로 관리한다. 단계별 구현 순서는 허용하지만 축소 권고안을 최종 범위로 대체하지 않는다.
- Frontend와 AI가 조기에 자유롭게 테스트하고 Backend도 반복 고도화할 수 있도록 개발용 Supabase와 Backend Preview 구축을 첫 실행 gate로 둔다.
- AI가 포함된 엄격한 MVP이므로 실제 추론·fixture·fallback·모델/데이터 version·평가 결과를 구분한다.
- 단계와 완료 gate는 [통합 로드맵](ROADMAP.md)을 따른다. TPO·OOTD 정책 등 기존 미결 사항은 별도 결정 전까지 미결로 유지한다.

## 1. 제품 요약

실제 소유한 옷을 한 번에 등록하고 날씨와 취향에 맞춰 조합하며, 코디 보관·착용 기록·소셜 영감을 연결하는 AI 패션 모바일 앱.

주 타깃은 패션/OOTD에 관심 있는 10~20대 여성, 보조 타깃은 준비 시간을 줄이고 싶은 20~30대 직장인·대학생이다. 디자인은 키치한 무드와 단순한 UX를 지향한다.

차별화 가설은 다중 의류 등록으로 등록 부담을 낮추고, 보유 의류 기반 추천과 따라입기를 제공하는 것이다. 경쟁 서비스의 현재 기능/단점, 평균 40분 등록 시간 등 초기 제안서의 시장 주장은 이번에 검증한 사실이 아니다. 에이클로젯을 참고하되 복잡도를 줄이고 필요한 기능을 재구성했다는 설명을 사용할 수 있으나 구체적인 비교 근거는 별도 확보해야 한다.

## 3. 제외/미래 확장

- 쇼핑몰 로그인·주문내역 스크래핑과 Google Calendar 연동은 역할표에 취소 표시. 뒤의 Supabase 설명에 남은 캘린더/쇼핑 서버 문구는 삭제 대상 후보다.
- 쿠팡 파트너스 링크, 쇼핑 플랫폼/브랜드 협업, 옷장 빈틈 기반 구매 추천, AI 트렌드 수집은 Future Work. 제휴 체결·수익 확보 사실이 아니다.
- 앱 매각은 가능한 사업 결과 아이디어이지 현재 수익 모델/개발 기능이 아니다.
- 댓글·주간 프리뷰·퍼스널컬러·체형은 초기 IA에는 있지만 최신 기능 표에 명확한 확정이 없어 현재 필수로 추가하지 않는다.
