# 마피코 PRD — 최신 요구사항 정리

## 플랫폼 결정 출처 및 현재 재확인 상태

- **모바일 웹 우선의 근거는 팀 회의록이 아니라 사용자 채팅**의 "모바일 웹으로 우선해보는 것으로 가시죠"라는 지시다. 로컬 [9/26 회의 정리본](../../records/meetings/2026-09-26.md)에는 플랫폼을 모바일 웹으로 결정한 내용이 없다. 정리본만 확인했으므로 원문 회의 전체에 대한 단정은 하지 않는다.
- 모바일 웹은 **모바일 브라우저에 최적화한 웹 서비스**이며 앱과 웹 사이의 별도 플랫폼을 뜻하지 않는다. 네이티브 앱·앱스토어 출시·PWA 기능 도입은 확정하지 않았다.
- 빠른 링크 공유·임시 배포·초기 FE/BE 연동을 고려한 모바일 웹 우선 이유는 **개발 측 제안**이지 팀 회의에서 확정한 선정 근거가 아니다.
- 현재 사용자는 회의 근거와 용어·선택 이유를 재확인하는 질문을 했다. 이를 플랫폼 변경 지시로 해석하지 않는다. 기존 사용자 지시에 따른 우선 진행 방향은 유지하되, 설명 후 재확인할 사항으로 기록한다.

## 2026-09-28 최신 논의 우선 반영

이 블록은 아래 초기 명세와 과거 결정 해석보다 우선한다.

- **추구미 개수는 5종으로 확정**, 최종 이름과 분류 정의는 선정 대기다. 종전 페미닌·Y2K·미니멀·그런지·캐주얼 목록은 이전 제안/구현 seed 이력이지 최종 5종이 아니다.
- 범용 스타일보다 **세부 Aesthetic 방향을 선호**한다. 클린걸·모리걸·다크 아카데미는 후보 예시이며 확정된 3종으로 계산하지 않는다.
- 초기 검증은 **여성 의류·패션 중심**이다. 남성용 스타일 확장은 선택적 후속 설계로 고려하며 이번 모델 구현이나 정확도 달성을 확정하지 않는다. 사용자 성별을 서비스 이용 제한으로 삼지 않는다.
- **모바일 웹 우선은 사용자 채팅 지시에 따른 진행 방향**이다(회의 확정 아님; 현재 의미·선택 근거 재확인 중). 과거에는 실제 MVP의 기능별 포함/제외가 미확정이었으나, 2026-09-29 사용자가 정본 ERD 전체를 엄격한 MVP에 포함하도록 정정했다. 단계별 축소 제안을 팀 승인 범위로 대체하지 않는다.
- 근거·수집 계획: [MVP·추구미·데이터 계획](MVP_AND_DATA_PLAN.md). 모듈 분리와 선택적 확장: [AI 아키텍처](../backend/AI_ARCHITECTURE.md).

## 2026-09-29 MVP 실행 범위 정정 (최우선)

- 사용자는 현재 정본 ERD의 전체 내용이 MVP에서 구현되어야 한다고 확정했다. 22개 public 테이블은 schema 존재뿐 아니라 제품 흐름·내부 job·권한·테스트에서 실제 사용되어야 한다.
- 현재 OpenAPI 50개 operation은 별도 계약 변경으로 제외하지 않는 한 MVP 구현 대상으로 관리한다. 단계별 구현 순서는 허용하지만 축소 권고안을 최종 범위로 대체하지 않는다.
- Frontend와 AI가 조기에 자유롭게 테스트하고 Backend도 반복 고도화할 수 있도록 개발용 Supabase와 Backend Preview 구축을 첫 실행 gate로 둔다.
- AI가 포함된 엄격한 MVP이므로 실제 추론·fixture·fallback·모델/데이터 version·평가 결과를 구분한다.
- 단계와 완료 gate는 [통합 로드맵](ROADMAP.md)을 따른다. TPO·OOTD 정책·최종 5종 명칭 등 기존 미결 사항은 별도 결정 전까지 미결로 유지한다.

기준: 2026-09-28 사용자가 대화에 제공한 초기 제안서, 개발기능/역할/일정, 기능 ID 표, PRD 초벌, 9/26 통화 요약. 원문 전체 전사가 아닌 정리본이다. 링크의 Notion 본문은 직접 읽지 못했으며 PDF·스크린샷·디자인 이미지 파일 자체도 제공되지 않아 검토하지 않았다.

- **MyFit:Core = 마피코**. 영문과 한글 표기이며 같은 이름이다(2026-09-28 사용자 정정). 이전 명칭으로 분류하지 않는다.

- 초기 제안서와 최신 기능명세가 충돌하면 최신 명세를 우선하되 회의의 '검토/확인 필요'를 확정으로 바꾸지 않는다.
- 취소선은 제외 방향으로 읽지만 같은 기능이 다른 부분에 잔존하면 충돌로 남긴다.
- 기존 에이전트의 M0.5 축소 권고는 팀 합의가 아니다. 제품 범위와 구현 단계 제안은 구분한다.

## 1. 제품 요약

실제 소유한 옷을 한 번에 등록하고 날씨와 취향에 맞춰 조합하며, 코디 보관·착용 기록·소셜 영감을 연결하는 AI 패션 서비스.

주 타깃은 패션/OOTD에 관심 있는 10~20대 여성, 보조 타깃은 준비 시간을 줄이고 싶은 20~30대 직장인·대학생이다. 디자인은 키치한 무드와 단순한 UX를 지향한다.

차별화 가설은 다중 의류 등록으로 등록 부담을 낮추고, 보유 의류 기반 추천과 따라입기를 제공하는 것이다. 경쟁 서비스의 현재 기능/단점, 평균 40분 등록 시간 등 초기 제안서의 시장 주장은 이번에 검증한 사실이 아니다. 에이클로젯을 참고하되 복잡도를 줄이고 필요한 기능을 재구성했다는 설명을 사용할 수 있으나 구체적인 비교 근거는 별도 확보해야 한다.

## 3. 제외/미래 확장

- 쇼핑몰 로그인·주문내역 스크래핑과 Google Calendar 연동은 역할표에 취소 표시. 뒤의 Supabase 설명에 남은 캘린더/쇼핑 서버 문구는 삭제 대상 후보다.
- 쿠팡 파트너스 링크, 쇼핑 플랫폼/브랜드 협업, 옷장 빈틈 기반 구매 추천, AI 트렌드 수집은 Future Work. 제휴 체결·수익 확보 사실이 아니다.
- 앱 매각은 가능한 사업 결과 아이디어이지 현재 수익 모델/개발 기능이 아니다.
- 댓글·주간 프리뷰·퍼스널컬러·체형은 초기 IA에는 있지만 최신 기능 표에 명확한 확정이 없어 현재 필수로 추가하지 않는다.

## 5. KPI·승인 조건의 상태

초기 목표: 온보딩 85%, 배치등록 75%, 추천채택 40%, D7/D30 45%/25%, 공유/스크랩 20%. 측정 결과가 아닌 목표다. 15종 선택+첫 3벌 등록을 온보딩 완료로 보는 기존 정의는 5종/튜토리얼 건너뛰기와 충돌해 재정의가 필요하다.

6벌 분할 2초·분류90%·파이프라인1.5초는 장비·입력·네트워크 포함 여부·평가셋·p95 정의 없는 목표다. 추천 7시 렌더링과 최신 메모의 5시 생성도 아직 하나로 정리되지 않았다.
