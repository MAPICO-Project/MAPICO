# MVP 범위 검토

## 결론

제안서에 적힌 MVP는 `CV 파이프라인 + 추천 시스템 + 날씨/캘린더 + 소셜 네트워크 + 유사도 검색`을 동시에 포함합니다. 학기 프로젝트의 첫 릴리스라면 한 번에 검증하기에는 범위가 큽니다. 제품 비전은 유지하되 릴리스를 세 단계로 나누는 것이 좋습니다.

## 권장 단계

### M0 — 기술·UX 검증

- 게스트 또는 최소 로그인
- 추구미 선택 1~3개
- 2~6벌 Flat Lay 이미지 1장 업로드
- 개별 의류 검출·분할 결과와 카테고리 수정
- 온도·강수와 수동 TPO 기반 코디 3종
- 추천 이유 및 오늘 입기
- 소셜 피드는 고정 샘플 데이터
- 샘플 OOTD 1개에 대한 내 옷장 매칭 데모

### M1 — 서비스형 MVP

- 실제 계정, 이미지 저장, 디지털 옷장 CRUD
- 위치 기반 기상청 연동
- OOTD 캘린더
- 추천·등록 행동 이벤트 수집
- 비공개/공개 OOTD 게시와 스크랩
- 제한된 추구미 피드

### M2 — 소셜 확장

- 댓글·좋아요·팔로우 또는 랭킹 정책
- 실제 사용자 콘텐츠 기반 Styling Mimic
- 벡터 검색 인프라
- 개인화 학습과 옷장 통계
- 오전 7시 프리컴퓨팅·알림

## 승인 조건 재정의

### 2초 이내

업로드 포함 여부, GPU, 이미지 해상도, 서버/클라이언트 측정 시작점이 필요합니다. `업로드 완료 후 API 수신부터 결과 JSON 반환까지의 p95`처럼 정의해야 합니다.

### 카테고리 정확도 90%

다중 객체에서는 Detection recall, mask 품질, classification Macro F1과 실제 저장까지의 end-to-end 성공률을 따로 측정해야 합니다.

### 매칭률

코사인 유사도 원값은 확률이 아닙니다. 사용자 표시용 점수로 보정하거나 `매우 유사/유사/대체 가능` 등의 등급으로 표현하는 편이 안전합니다.
