# PRD 피드백·TPO 결정·백엔드 로드맵 정리

## 요청

최신 회의 내용을 바탕으로 PRD 피드백, TPO 포함 여부, 백엔드 작업기간을 팀에 전달 가능한 형태로 정리합니다.

## 결론

- TPO는 PRD에 포함하되 P0에서는 수동 프리셋과 룰 기반 점수로 구현합니다.
- 5개 추구미와 TPO를 결합한 25개 클래스를 새로 학습하지 않습니다.
- M1 백엔드는 1인 기준 8주 + 1주 버퍼, 약 39~43 인일로 산정합니다.
- 전체 소셜과 실제 벡터 검색까지 포함하면 11~14주가 필요합니다.
- PRD는 제품 비전과 제출 MVP를 분리하고 성능 지표의 측정 조건을 보완해야 합니다.

## 후속 반영

- Opus 5.5 병렬 검토 3개 트랙으로 PRD/API, Supabase·Vercel 일정, TPO·인터뷰를 교차 검토했습니다.
- 첫 2~3일 계약 스프린트 후 PRD, API/DB, Backend 기반, AI mock을 병렬 진행하는 안으로 정리했습니다.
- Supabase·Vercel 기준 M1을 1인 6.5~7.5주 + 버퍼 1주로 보정했습니다.
- `api/openapi.yaml`에 18개 path의 OpenAPI 3.1 초안을 만들고 YAML 파싱을 검증했습니다.
- CV 추론은 외부 GPU Worker, 이미지 업로드는 Supabase Storage 직행으로 경계를 확정했습니다.
